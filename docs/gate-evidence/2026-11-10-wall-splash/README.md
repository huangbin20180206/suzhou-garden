# 墙面光斑：灯笼的光只有地面一圈，投不到墙上（2026-11-10）

## 一、缺的是什么

灯笼原有的「光斑」只有一个：`src/12d-lantern.js` 里的 `_groundSplashMat`，一张圆形光晕贴在地面上方 +0.06m。
夜里有墙的地方，灯光本该在墙面（尤其廊墙、粉墙）上留一片亮，实际一片都没有 —— 墙是死的，灯只照地。

用户 2026-11-10 指出的三条观感缺口之一（另两条：荷叶水珠、拖拽划水，见 `2026-11-10-lotus-drops-drag/`）。

## 二、修法（判据未动，`probe/` 一行未改）

位置：`src/12d-lantern.js` 灯笼循环末尾（`lanternGroups.push(pivot);` 之后）。

- 只在 `WITH_VOL && _groundSplashMat` 时执行 —— 与地面光斑同一个画质门控，低档不出、不额外吃性能。
- 从灯芯 `(x, y, z)` 朝 ±x / ±z 四个方向各打一条射线（`_wr.far = 3.2`，`intersectObject(world, true)`）。
- 命中筛除：`name === 'wallSplash'` / `'lampVol'`（不叠在自己身上）、材质为 `_groundSplashMat` / `lampVolMat` 的命中（那是地面光斑与体积光，不是墙）、`distance <= 0.6`（贴脸的假命中）、`|法线.y| >= 0.35`（地面/屋顶，不是竖直面）。
- 命中后贴一张圆斑：复用 `_groundSplashGeo` + `_groundSplashMat`，`position = hit.point + n * 0.02`、`lookAt(_from)`、半径 `pr = Math.min(1.35, 0.5 + (3.2 - hit.distance) * 0.35)`、`name = 'wallSplash'`，并入 `_splashMeshes` 交给既有的 `tickLampVol` 统一喂 uLamp / uTime。
- 一盏灯命中一面墙就 `break` —— 只贴最近那一面，避免同一个灯笼把两面墙都点亮成「两头亮」的假象。

为什么不新建材质：uLamp / uTime 由既有 `tickLampVol` 统一更新，复用材质等于零新增接线点；同一盏灯照出的地面斑与墙面斑必须同步呼吸，两种材质迟早会走样。

代价：每盏灯 4 条射线，只在建场期跑一次（不进逐帧路径）。

## 四、哪条不能当证据

1. **人眼观感没有确认。** 截的夜景机位钻进廊顶与墙后，画面基本全黑（1280×720 那张）。本包只证明「斑生成了、落在墙上、数量与门控一致」，不证明「好看」。观感要另选机位重截。
2. **`draw calls=388` 不能与上一批的 368 直接比。** 同一批代码两次 smoke 会落不同档位（无头 ANGLE 随机给 Intel Iris Xe 或 RTX 4060），这是项目 2026-10-19 已定案的档位漂移，不是本次新增的绘制量。
3. **`warmboot-guard` 首帧段这条红，不能记在本次改动头上。** 见下节。

按项目铁律**不放宽 800ms 阈值**：它守的是「编译不许堵在渲染循环入口」，放宽等于把这条守卫废掉。

## 六、没做的

- 墙面光斑的**形状**是圆的（复用地面圆斑几何）。真实灯笼投在墙上的光斑会被窗棂、栏杆切出格纹，那需要单独的几何/贴图，本次没做。
- 只处理 ±x / ±z 四个方向。斜 45° 的墙（比如影壁转角）打不到。
