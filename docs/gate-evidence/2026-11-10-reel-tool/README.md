# 2026-11-10 · 时光流转门（reel-guard）：画面其实一直在跟，红的是量具

**状态：已修复（只改量具的取样范围，绝对下限 0.5 一个字没动）。**

## 一、现象

`probe/reel-guard.mjs` 的判据「画面随流转实时更新（不是只改了数值）」在 2026-11-10 午间连跑三次全红：
diff **0.075 / 0.051 / 0.066**，阈值 0.5（见 `00b-before-original-reds.log`）。
按字面这就是「时光流转只改数字不改画面」——一个足以立 P0 的缺陷。**结论是错的，错的在量具。**

## 二、定位（三条实测，按先后）

### ① 同一段代码、同一台机器，四次跑读到 0.393 / 0.547 / 0.571 / 0.868
单跑四次 `probe/reel-guard.mjs`（`00-before-wholeframe-4runs.log`），跨度 **2.2×**，
一次红、三次绿，没有一次改动过 `src/`。说明这条判据不是「稳红」，是**贴着 0.5 上下翻**。

### ② 满屏里有 68.4% 的像素永远不会动
诊断脚本 `reel-occl-20261110.mjs`（原文留档 `reel-occl-20261110.mjs.txt`）实测：
640×480 画框里 `#env` 抽屉占 **618×340 @(10,62)** ⇒ **68.4% 恒定面板**。
判据取的是「全屏均值差」，分子里那些像素恒为面板底色，分母却被它们填满；
滑杆读数与按钮文案的切换又把分子搅动。**信号被稀释、噪声被放大，方向正好相反。**

### ③ 同一对帧，两种口径差 2.5 倍
从 `00c-calibration-both-statistics.log`（三次标定跑，两种口径并列输出同一段帧）：

| 跑 | 全屏口径 | 去掉抽屉口径 |
|---|---|---|
| cal-8 | 0.542 | **0.912** |
| cal-9 | 0.729 | **0.910** |
| cal-10 | 0.861 | **0.916** |

全屏口径第三次比第一次高 59%，去抽屉口径三次差 **0.7%**。同一段代码，稳定性差 80 倍。

## 三、修法

只改 `probe/reel-guard.mjs` 的**取样范围**：新增 `frameMeanOutside(im, rect)`，
统计时跳过抽屉矩形内的像素；判据、阈值（`Math.max(0.5, idleBase3Out * 1.5)` 结构）、
`check()` 的名字与文案全部沿用。`src/` 一行未动——产品侧本来就没有缺陷。

## 五、哪条不能当证据

- **0.360**（`reel-after-1.log` 的全屏口径）看起来像「画面没跟」，它只是同一对帧用旧口径算的结果；
  用它可以证明「旧口径会把绿算成红」，不能用来证明产品有缺陷。
- 缺陷态 0.103 / 0.119 里有一份来自 HUD 时钟文字仍在变（画布定格但 DOM 在动），
  所以它不为 0；这不是噪声，是「缺陷态」应有的形状——`hour` 在走、画面不动。
- 本门只证明「整体亮度跟着时辰走」，**不证明**影子方向、水面反射、PMREM 环境贴图的更新时机；
  那几项各有专管门（`lamp-guard` / `refract-guard` / `pmrem-env`）。
