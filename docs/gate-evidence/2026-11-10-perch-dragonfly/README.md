# 2026-11-10 · 停栖蜻蜓在默认机位只有 14px（被叶子挡住）→ 25px

## 1. 缺陷
`probe/legibility-guard.mjs` 长期红，唯一红项：

```
✗ 默认机位能看到：停栖蜻蜓（A/B 差分 > 15px） — 14px（2 个对象）
```

门的量法：把 `G.perchingDragonflies` 全部藏起来再渲一次，数「三通道差 >12」的像素个数。14px 意味着两只蜻蜓加在一起只贡献 14 个像素 —— 等于看不出来。

## 2. 定位（先量，再改）
诊断 `probe-perch-px.mjs.txt`（默认机位，`?tier=low`，相机 `(-20,17,32)` fov 46）逐只量：

两件事同时成立：
1. **第 1 只被完全挡住**：视线在 36.31m 处先撞上 35.93m 的叶子 ⇒ 它一个像素都没露出来（不是尺寸问题）。
2. 池中 48 个锚点离默认机位全部 34.9~41.5m（最近 34.93、最远 41.48），换叶子挪不了多远；单靠"挪近一点"救不回来。
3. 叶盘贴水面（y≈0.15），俯角下必然被邻叶遮；花有约 1m 的花梗把落点抬出叶面，视线通畅。

## 3. 修法（判据一个字没动）
`src/08c-aquatic.js` 的 `pickPerchAnchor()`：候选里**有花就优先停花**，没有花时仍可停叶（保留冬/秋花少的兜底）。

```js
const flowers = cands.filter(a => a.kind === 'flower');
const pool = flowers.length ? flowers : cands;
return pool[(perchRnd() * pool.length) | 0];
```

- 两只各占一朵（原有的 `excludeId` 排除同实例机制不变，所以不会挤在同一朵上）。
- `PERCH_LIFT = 0.028` 没动：挡住它的是 0.38m 外的叶子，抬 2.8cm 救不了。
