# 2026-11-16 桌面端升级 · ⑤第一人称自由行走

## 一、要解决的问题

桌面端原来只有自动巡游，玩家不能自己走。本轮加「第一人称自由行走」：
按钮或快捷键进入，WASD/方向键走，按住右键转头，Esc 退出并恢复原来的浏览相机。

真园子验收时撞到一件真缺陷：**月洞门过不去**。玩家从南院出发朝北走，走到 z=23.62 就停住，
前面那 0.3 米像是有一道看不见的坎。

## 二、查到的根因

- 挡人的是一个 4m 宽、0~0.22m 高的竖直面，位于 z=23.3、属合并静态网格（`outputs/_diag/tri-20261116.mjs`）。
- 顺中轴 0.2m 粒度量地表（`outputs/_diag/fine-20261116.mjs`）：
  `z=23.4:-0.33 → z=23.2..22.0:0.22 → z=21.8:-0.42`。
  即门前铺装 -0.33、门槛石顶 0.22、门内园地 -0.42。
- 门槛石是按**绝对坐标**建的：`src/07-ground.js:125-128`
  `const sill = mesh(box(4.0, 0.22, 1.4), MAT.stoneDark, { name:'threshold' }); sill.position.set(0, 0.11, D/2 + 0.1);`
  顶面 y=0.22，而这一带地形在 -0.33 ~ -0.42 ⇒ 实际台阶 **0.55~0.64m**，
  原来的抬腿上限 0.34m 跨不过去，园门等于被封死。

## 三、修法（改产品侧，不动判据）

`src/11a-walk.js`：

1. 抬腿上限 `CLIMB` 0.34 → **0.60**，下台阶上限 `DROP` 0.65 → **0.70**（原值对 0.64m 的下落只余 1cm）。
   同时把找地面的射线起点抬到 `base+CLIMB+0.05`，否则射线起点在台阶顶面以下，根本打不到台阶。
2. 脚踝那条碰撞射线会先撞上台阶的**立面**，于是加「能不能踩上去」的判断：
   在命中点后 0.12m 往下打短射线，顶面高度 ≤ 抬腿上限且是水平面 ⇒ 当台阶放行；
   顶面够不着（栏杆 0.73m、假山、墙）⇒ 照旧拦人。

代价说明（大白话）：抬腿上限从 0.34 提到 0.60，等于园子里 0.6m 以内的矮台子都能踩上去。
栏杆、假山、池岸这些高于 0.6m 的东西一点没放松——三条射线照旧拦，池子照旧进不去。

## 五、哪条不能当证据

- `walk-09.log` 是**改一半时的红**：只抬了抬腿上限、没加「能不能踩上去」的判断，
  脚踝射线仍被台阶立面挡住，所以还是 z=23.62。留它是为了成对留存，不能当结论。
- 截图是无头软渲染（1~18 fps）出的，只能证明「位置到了、画面没穿模」，
  不能当帧率或画质证据。
- 走进园子后正面是一片垂柳枝条（`02-walk-inside-garden.png`），
  这是既有布局（柳树正好在中轴上），不是本轮改动引入；要不要给柳树让路另议。
