## 三、为什么不能直接判成缺陷

这三条红都在**墙钟时间**上，本机是核显/中端机型，两条门又各自要开全新浏览器冷启动：

- 首帧段判据 800ms、实测 801.5 / 804.8 / 900.8 / 919.0 —— 同一条门在同一天的不同提交上摆动近 120ms；
- 总时长判据 +35%、实测 +42%~+52% —— 冷缓存与后台进程都在里面。

按项目既定纪律（「判定为失败前必须先确认显卡档位；判据不因压线而放宽，一律从产品侧改」），
这里的正确动作**不是**把 800ms 改成 1000ms，而是：把两条读数固定下来（本目录），
在**有独显的空闲机器**上再取一次；若那时仍红，才去产品侧查暖编译的分段是否真的退化了。
