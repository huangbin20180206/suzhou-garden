# 2026-11-11 · 路旁石灯笼 8 盏真光源提前建（冷启动 −35%，最长帧 26.6s → 3.8s）

## 3. 根因

three.js 把**灯光数量**写进每个材质的着色器编译宏（`NUM_POINT_LIGHTS` 等）。
场景里 0 盏 PointLight → 8 盏，**全场每个 program 都作废、重编一遍**。

而这 8 盏灯原本是在 `15e-stable.js` 的 `makeStable()` 里建的，`makeStable()` 又被
`08-assemble.js` 的「马厩」**延迟批**（`deferBootFirst`）调用 —— 那已经**过了暖机**
（`11-loop.js` 的 `warmBoot`）。于是这轮重编谁也盖不住，全部落在首帧之后的某一帧里同步阻塞。

`15e-stable.js:556` 的原始注释只算过它对**帧率**的影响
（"8~11 fps，约 35~50%"），**没人算过它对启动时间的影响**。

## 4. 改法

把「建灯」与「建模型」拆开，灯提前到暖机之前建：

- `15e-stable.js` 新增导出 `stableRoadLampSpots(curve)` —— 桩位表提成模块级**纯函数**，
  灯与模型共用同一份真值（两条路径各建自各的曲线，控制点表相同 ⇒ 桩位逐位一致）。
- `15e-stable.js` 新增导出 `prebuildStableRoadLamps()` —— 建 8 盏 PointLight、
  推进 `worldLights`。**幂等**：已建过直接返回 false。
- `15e-stable.js` 的 `makeStableRoad()` 里删掉建灯段，改为一句日志。
- `08-assemble.js` 在 `mergeStatics(world)` 之后、`fitShadowCamera()` 之前调用
  `prebuildStableRoadLamps()`，并加 `bootMark('路灯真光源')`。
- `08-assemble.js` 的「马厩」延迟批里再调一次 `prebuildStableRoadLamps()` 兜底（幂等，不会重复加灯）。

三条位置约束（缺一条就白建，已写进代码注释）：
1. **在暖机之前** —— 暖机走真实 `composer.render` 编着色器，灯晚进场就是"0→8 盏"重编；
2. **在 `mergeStatics(world)` 之后** —— 避免被任何"遍历 world 收静态件"的逻辑误伤；
3. **在 `initEnvScene()` 之前** —— 那里 `collectSeasonCaches`/`applyEnv` 要遍历场景。

灯数、强度、衰减、相位公式、`low` 档不建的预算规则**一个字没动**。

`i` 的取值域也一致（0~7）。这是判据本身的脆弱性，不是本次改动。
