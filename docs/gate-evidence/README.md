# 门禁证据落盘约定

状态：**现行约定**（2026-11-10 建立，不是待办）。

## 为什么要有这个目录

`outputs/` 被 `.gitignore` 第 12 行整目录忽略。门禁默认把日志、截图、诊断样张都写在 `outputs/` 里 ——
这意味着**盘上有、推上 GitHub 一个字节都没有**。后果：

- 事后想把结论再核一遍，只能在最初那台机器、那个工作副本里核；
- 别人（另一个 AI、另一个会话、换一台电脑）克隆下来，看到代码变了，但**没有任何读数能证明改对了**；
- 「代码与基线同笔提交」这类事故无法事后拆开：分不清是产品改对了，还是把标准答案一起挪了。

所以凡是**要拿来当结论依据**的读数，必须落到本目录（`docs/gate-evidence/`）并随代码一起提交。

## 目录与命名

```
docs/gate-evidence/<YYYY-MM-DD>-<主题>/
```

- 主题用短横线小写英文或短中文，能一眼看出改了哪块（例：`2026-11-10-actor-tick`、`2026-11-10-lantern-atten`）。
- 文件按"序号-角色"命名，序号表示读数发生的**时间顺序**：
  - `00-before-<门名>.log` — 改动之前的读数（必需）。**这一份必须早于任何编辑**，否则不算改前。
  - `01-after-<门名>.log` — 改动之后的同一条门
  - `02-after-<别的门>.log` — 为确认没牵连而顺带跑的门（要标注"不是用来证明修复有效"）
  - `*-on.png` / `*-off.png` — 需要像素证据时附样张
- 每次证据包都要有 `README.md`，写清四件事：**缺陷是什么（带文件行号与原文）→ 怎么修的 → 改前/改后读数对照表 → 哪一条读数不能当证据用（诚实标注）**。

## 门槛

- **成对**：改前红 + 改后绿，缺一份就不算证据；只有改后的绿，等于只有结论没有前提。
- **可指回**：每个数字要能指回一次真实的测量（哪个门、什么时候跑的、原始输出在哪个文件）。
- **不改判据**：判据文件（`probe/*.mjs`）不因为改动而放宽；要动判据，另立一笔并单独说明为什么。
- **不同笔**：代码改动与基线文件（`layout-fingerprint` 指纹、`actor-sim` 基线）分两次提交，
  否则事后无法区分"改对了"与"基线被糊了"。
