## 一、右下角调试面板：技术指标只给调试态

### 问题
`index.html:61` 的 `#stats` 是常驻元素，`11-loop.js` 每 0.5s 往里写：

```
40 fps
draw calls  590
triangles   3,357,567
geometries  464
textures    121
风和日丽 · 午夏
画质 自动 · 性能档 · 无 AO · 超采样 1x · QoS L0
按 0 复位视角 · 拖动旋转 / 滚轮缩放（可推到 1.6m）
双击任意物体＝聚焦到它 · 右键拖动＝平移（走到院角看细节）
```

前七行是给开发看的。**朋友打开会看到这块，读作"这是半成品"**。
老黄反复测试时从没觉得有问题 —— 因为本机会话里它就是"正常的开发界面"。

### 但整块删掉也不行
最后两行是**唯一**常驻告诉用户"这个画面可以动"的线索。删了更不知所措。

### 改法
按 `GARDEN_DEBUG`（= `isDebugSurface`）分两档：

| 访问来源 | 显示内容 |
|---|---|
| `?debug=1` / 自动化驱动 / 本机（localhost、127.0.0.1、file://） | 全量（技术指标 + 操作提示） |
| **公网访客** | 只有操作提示两行 |

⚠️ **隐藏技术指标不影响 QOS**：`QOS.sample(fps)` 在上一行照常跑，只是不再把数字写进 DOM。
⚠️ 复用的就是 `00a-quality` 那个已有判据，没有新造一套 —— 老黄本机调试体验一位不变。

### 验证（`01-stats-visible.log`）
- `isDebugSurface` 六个分支逐一验过（公网 false / 本机 true / file:// true ...）
- `?debug=1` 实测：技术指标与操作提示都在
- 无头环境 `navigator.webdriver=true` ⇒ 恒走调试支，**公网那一支在这里测不到**，
  依据是上面那条纯函数的六个用例（`npm run unit` 覆盖）。

## 二、引导被"随手一点"关掉：加 2.5s 静置期

### 问题
`bindGuide` 的 dismiss 监听的是 **capture 阶段**的 `pointerdown`：

```js
const dismiss = (e)=>{ if (GUIDE.on && !closest('#guide')) guideStop(); };
addEventListener('pointerdown', dismiss, true);
```

⇒ 用户进来后**任何**一次点击（哪怕只是想拖一下画面）都会当场把引导关掉，
而他还没读到第一句。引导一关就写 `localStorage`，之后**再也不弹**。

这正是老黄说的"不知所措"的另一半：他想看引导，但它已经被自己的第一次点击吃掉了。

### 为什么原来这么写
注释写着"用户已经会用了就别再教"。这个意图对**已经用过的人**成立，
但对**第一次进来的人**不成立 —— 而引导本来只对后者显示。

### 改法
引导出现后 **2.5 秒内**的交互不关闭它，之后恢复原行为（首次交互即消失）。

```js
const GUIDE_HOLD_MS = 2500;
if (performance.now() - (GUIDE.shownAt || 0) < GUIDE_HOLD_MS) return;
```

- `GUIDE.shownAt` 在 `guideStart()` 里写，**不改 `guideStart` 本身的行为**；
- ⚠️ 为什么不在 bindGuide 里劫持 `guideStart`：它在 `11-loop.js:2115` 就被拷进
  `__GARDEN_FULL` 暴露给门禁了，重赋值只改本地名、门禁拿到仍是原函数，两边行为不一致；
- 点气泡上的「跳过 / 下一步」**不受**静置期限制 —— 那是用户的主动选择；
- 静置期只影响"关不关"，**不影响底下画布**：引导容器是 `pointer-events:none`，
  这 2.5 秒里用户照样能转视角。

### 验证（`02-guide-hold.log`）
实测：
```
收层后引导显示: true
  静置期内点击画布 => 仍显示 ✓
  静置期后点击画布 => 被关 ✓
```

### ⚠️ 门禁判据同步改了，这是有分量的
`guide-guard` 第 6 组原来断言"点了就消失"，静置期让前 2.5s 不消失 ⇒ 报红。

**处置：判据本身不改，只把"先等多久再点"从 220ms 抬到静置期之后。**
三条原判据一字未动（`引导显示中遇到 pointerdown/wheel/keydown 即消失`），全部仍在。
另外**新增三条负例**：静置期内点了不该消失。

负例自检（把 `GUIDE_HOLD_MS` 改成 0）：
```
✗ 静置期内遇到 pointerdown 不消失 — true→false
✗ 静置期内遇到 wheel 不消失      — true→false
✗ 静置期内遇到 keydown 不消失    — true→false
```
⇒ 三条全部报红，说明新判据有牙，不是永真。
