## 3 · 未提交的两件事（已各自验收）

### A) 老黄报的 bug：狂风暴雨时涟漪画到岸上草地 ✅ 已修已验

- **根因**：雨滴涟漪按**外接椭圆**撒点（半轴 12.5×6.4、心在世界 (0,3)），而池形是**不规则多边形**
  （`POND_PTS`/`POND_RADII`）⇒ 椭圆边缘落到岸上（涟漪环画在 y=水面+0.08，岸上是平草地 y≈0 ⇒ 浮在草皮上方）。
- **修法**：拦在**唯一入口** `spawnRipple()`（`src/06-vegetation.js`）：`if (!insidePond(x, z - 3.0)) return;`
  —— 雨滴/点击/鱼跃/泳龟一起受保护。**坐标口径**：`insidePond` 是**池心局部坐标**、池心在世界 **z = +3**
  （与 `07-ground.js` 的 `dz = z - 3.0`、`06-vegetation` 里 `z = 3 + sin(ang)*rad` 一致）。
- **连带修**：`src/11-loop.js` 点击判定原来 `worldToLocal(hit.point)` 后读 `lp.z`（水面 mesh 带 `rotation.x=-π/2`
  ⇒ 局部 z ≈ 0）⇒ 岸边点击也判"在池内"；改成 `insidePond(hit.point.x, hit.point.z - 3.0)`。
- **新门禁** `probe/ripple-bounds.mjs`：读**涟漪池实例落点**断言"所有活跃圈都在池域内"。
  **TDD 证据**：未修代码上红在越界那条（例 `(0.31,-3.23)`）；修复后 3449 个样本全在池内 + 正向对照（池心点击出圈）。

### B) 计划书第 2 项：水面反射按需更新 ✅ 已做已验

- **现状**：高档位下 Reflector 每帧把整场景再渲一遍（核显档本来就整条关掉）。
- **改为**：**相机在动 / 下雨 / 时光流转 / 长曝光** ⇒ 满速；都不成立才降频到**每 3 帧**
  （观景态，停滞上限 ~50ms）；停下后再满速 12 帧落定。
- **新门禁** `probe/reflect-adaptive.mjs`：用**速率比**判据（静止态 ≤60% 满速且 ≥15%、相机跳变 ≤2 帧内刷出、下雨须满速）。
- **连带**：`probe/lampvol-guard.mjs` 把该门水面反射**钉成每帧刷**（否则水面旧倒影会造出与光团无关的假热点）。

## 4 · 这个项目的**铁律**（动手前必读，违反会产生静默缺陷）

1. **全局随机流 `rnd()`/`rr()` 的调用次数不可变**：删/改任何消耗它的代码块，必须**原样保留调用次数、且空跑放回原位置**
   （"等量"必须"同序"）。要复核布局有没有漂，跑 `node probe/layout-fingerprint.mjs`（与基线比）。
2. **布局/装配类随机一律走专用种子流**（`06-vegetation` 的 `jr` / `08-assemble` 的 `jr`），**绝不用共享 `Math.random`**；
   运行期效果（涟漪、音景、风场调度、雨雪粒子）才用 `Math.random`。
3. **探针要采样场景内容时，必须 `await window.__garden.bootDonePromise`**，不能只等 `loading.done` + `sleep`
   （`loading.done` 在**延迟批之前**触发，柳/竹/立峰/桃要 ~1.0~1.1s 才进场景）。例外：`loading-guard`/`warmboot-guard`/`intro-guard` 是**故意**在启动期采样的。
4. **判据必须有牙**：阳性对照 + 负例自检 + **必须先断言前提**（例：测"观景态降频"要先确认"晴且水面静默"）。
5. **不许为了让门禁变绿而调阈值**；偶发红先怀疑 GPU 档位/就绪竞态，**别用静默重试掩盖**（`verify-all` 的重试会标注 FLAKY，绝不静默变绿）。
6. **长跑放后台** + 日志落盘（`outputs/_diag/`）。前台跑静默 5 分钟会被工具掐掉。
7. **同一个项目只开一个窗口**：今天被另一个窗口并发跑 verify 抢过 GPU（把我的探针饿到 240s 超时）。
8. **`sw.js` 的 CACHE 版本与内容绑定**：改了 cache-first 资产（`index.html`/`vendor.js` 等）必须 bump（`check` 门禁会验）。

## 5 · 今天踩过、以后别再踩的坑（细节见 `CODELY.md`）

| 坑 | 一句话 |
|---|---|
| **Chrome 有 shader 磁盘缓存** | 同一浏览器第 2、3 次加载复用已编译 program（总编译 6580→546ms）⇒ **只有冷启动代表真实体感**，性能 A/B 必须每次换浏览器实例 |
| **`onBeforeRender` 每帧被调用多次** | 主 pass + 折射 pass + AO 辅助 pass，且折射 pass 用**另一台相机** ⇒ 任何"比较上一帧相机/按帧计数"都必须**只认主相机** |
| **涟漪池的"活跃"判据** | 必须用 `instanceAlpha`，**不能用实例矩阵缩放** —— 回收时只置 alpha=0、不重置缩放 |
| **首帧渲染抛错的症状** | 页面**永久停在加载页**（`startAfterWarm` 里"隐藏加载层"的 rAF 链根本没被安排）；`pageerror-guard` 能抓 |
| **异步资产会改变时序** | GLB 是异步挂载的；探针/装箱若在"资产还没进场"时采样，结果会随冷热缓存漂 |
| **`customProgramCacheKey()` 长度不是复杂度代理** | 风材质共用同一个 `onBeforeCompile` 源码 ⇒ 长度相同；要按**渲染签名**（类型+贴图+状态+实例化/投影）分组 |
| **别把"余下对象也轮转摊匀"** | 暖编译装箱里那样做会让最坏帧 program 从 10 涨到 17（签名只是 program 的近似） |

## 6 · 排查线（遇到红门/怪现象按这个顺序）

1. **看是不是"偶发"**：同一门**单独重跑** 2~3 次。`verify-all` 的 FLAKY 标注已经帮你分了一次类。
2. **对 GPU 档位**：`_harness.mjs` 明说 ANGLE 每次挑哪块 GPU 不固定（实测 Intel Iris Xe=low 档 / RTX 4060=high 档，
   同场景 draw calls 308 vs 716）⇒ **像素类**判据的 σ/容差会随档位漂。每道门都打印 `[GPU]`。
3. **对就绪竞态**：探针是否只等 `loading.done` 而没等 `bootDonePromise`？（§4-3）
4. **对时间线**：老黄说"还是那样"时，先比**他截图的 unix 时间戳 vs 源文件 mtime**（页面会一直跑已加载的那份 JS，不刷新永远看不到新代码）。
5. **视觉判断用并排对照**：多模态单图描述会误报（同一个淡剪影单图会说"bright white"，并排让它选"哪栏更白"才稳）。
