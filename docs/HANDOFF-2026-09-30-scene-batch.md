## 3. 下一窗口开工必读（这批踩的坑，别再踩）

1. **用户实拍 > 探针全绿 > 我的多模态自查**。本批连续两次"我这边全绿、老黄说完全不能看"：
   程序化荷花被判"不像荷花"、大雁被判"这也太小了"。
   **给"屏幕上该出现的东西"写断言时，必须量"用户视角能不能看见"**——
   大雁那轮我调了三轮尺寸/高度/航路却从没量过"从池边抬头看不看得见"，
   结果 40m 外每只只有 4~5 像素、队形整体在画面外（0/13 可见）。这条已补进 `birds-guard`。
2. **观感类落点必须来自射线实测，不能手填**。小鸟我手填了假山最高峰(y=7.47m，远看 1~2 像素=白做)、
   又猜了高度(1.6~3.0m)，画面里就是"几只鸟浮在半空、脚下的石头对不上"。
3. **`insidePond` / `POND_RADII` 吃池局部坐标**（池心世界 `(0,+3)`，即 `y = 世界z − 3`）。传世界坐标会得出"岸上 N 片"的假数据。
4. **`npm run check` 只查语法，不查 ESM 导入/导出链接错误**。删任何 `export` 前必须 `grep` index.html
   ——它的**内联主模块**里还有一份 import 清单（本批漏过一次 ⇒ 页面停在加载页、探针全超时）。
5. **改 `index.html`（SHELL 成员）必须 bump SW 版本**（现 v12）。
6. **判据只断下限会诱发"调过头"**。彩虹那轮为了"能看见"把带宽/强度放大，结果 81% 的天空被染成乳白、
   虹只剩一道淡边 ⇒ 效果强度类判据要**同时断上限**。
7. **删/改任何消耗全局随机流的代码**：必须原样保留 `rr()/rnd()` 的调用次数与顺序，弃用也要 `void rr(...)` 空跑在原位（铁律 1）。本批的等量燃烧点在 `08` 的 `lotusSpots.forEach(s=>{ void rr(0.98,1.03); })`。
8. **提交信息带中文/括号时 PowerShell 内联 `-m` 会拆参**：先 `write_file` 写 UTF-8 消息文件，再 `git commit -F`。

## 5. 尚未收尾的诚实边界（本批主动交代，非缺陷）

- **大雁不保证"正对头顶"**：四朝向实测 20 秒内能看到雁的秒数 = 朝北 18 / 朝东 10 / 朝南 2 / 朝西 0。
  抬头**大概率**能看见一队，但要"一抬头就正对头顶"需让航线跟随用户视角（交互式设计），**没做**。
- **雨后初晴的彩虹仰角是被刻意抬高的**（方位仍严格背对太阳）。物理上正午看不到彩虹，
  而面板默认时段是正午——这是明确取舍，代码与门禁注释里都写了，别"修正"回去。
- **大雁/小花的低模感**是已知取舍（体长取真值一半、小鸟 BIRD_SCALE 2.2），老黄已接受"有点假但至少能看"。
