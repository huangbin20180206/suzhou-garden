## 2 · 铁律（违反会立刻出事，全部有前例）

1. **不要跑 `npm run verify`（全量 71 道）** —— 老黄明令：只在**最终交付前**跑一次。日常只跑 `npm run check` + 该改动相关的单项 + `npm run verify:quick`（12 道，4~6 分钟）。
2. **跑门禁期间绝不改 `src/`** —— 会造出"看起来像产品坏了"的假红（本轮两例：改了 `11-loop.js`、并发改 `08-assemble.js`，各让一道门出现假红）。
3. 改了 **`index.html`（PWA SHELL 成员）必须 bump `sw.js` 缓存版本**，否则用户看不到新版（要他 Ctrl+F5 或开无痕区分"代码问题 vs 缓存问题"）。
4. 布局/装配类随机**必须用文件内私有 `mulberry32(固定种子)`**，禁用全局 `rnd()/rr()/Math.random`（会让全园布局漂移）；删/改"吃随机流"的代码要**等量同序**空跑。
5. **新增 InstancedMesh / 换渲染载体 / 改池边等布局件的位置 ⇒ 必须重出 `probe/_baseline/layout-fingerprint.txt` 基线**（`node probe/layout-fingerprint.mjs --update-baseline` 后复跑确认）。
6. 改产品的"名字 / 类型 / 契约"时**必须 grep 所有探针**（含 `probe/*.mjs` 里的 `await import('/src/xx.js')` 动态导入）并同步翻面判据 —— 本轮就漏过 `censer-guard` 的句柄路径与 `birds-guard` 的全季节扫描。
7. **"人列名字清单必漏"**：搬代码/加依赖时，收尾一律真跑三门自查 —— `npm run check`（no-undef 逐行点名）、`import-audit`（说清该从哪个模块 import）、`node outputs/_diag/boot-error.mjs`（页面 ReferenceError / 起没起来）。
8. 天气×季节扫描类判据：**先设季节、再用 `window.__garden.weatherAllowed(w)` 问合法性**，不合法就跳过并计数（例：夏季 `setEnv('weather','snow')` 会被静默拒绝，本轮因此假红 8 条）。
9. **多模态观感批评只当线索**，必须回结构量核实（脚底−地面序列 / 纯黑材质扫描 / 投影 / 逐帧记录）；本项目已 4 次证明"看着像错"其实没错。
10. 交付口径：**每个任务先报预计时间**；汇报用大白话、别堆术语；不要用问句把任务推回去。
