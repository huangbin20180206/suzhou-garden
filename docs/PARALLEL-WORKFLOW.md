# 多任务并行工作流（2026-11-02）

> 给老黄自己看的操作说明。目标不是"同时开十条流水线"，而是**把一个大改动拆成几条
> 互不踩文件的小任务，各自在工作区里跑完、各自过门，再一条条合回来**。
> 配套脚本：`tools/task-worktree.sh`。

## 一、先说结论：这个项目能并行到什么程度

| 任务类型 | 建议并行数 | 原因 |
|---|---|---|
| 只读调研（查代码、量数据、写方案） | 3~4 条 | 不改文件，不会冲突 |
| 改**互不重叠**的文件 | 2 条 | 验证要抢 CPU，多开会互相拖慢 |
| 改同一批文件 / 动演员与马车的基线 | **1 条** | 必冲突：`.json.gz` 基线是二进制，冲突无法手工解决 |
| 全量 `npm run verify`（95 道门，约 90 分钟） | **1 条，独占** | 重量级浏览器门，并行会出假红 |

**一句话**：这个仓库的瓶颈不是 token，是**验证成本和你的评审带宽**。
一个 34 文件、+1300 行的提交，光看懂就要很久；并行只会让"要评审的量"成倍增加。

## 二、三条硬约束（都是踩过的）

1. **门禁会互相打架**。2026-11-02 实测：两道门同时跑，`warmboot-guard` 的
   "首帧 ≤ 800ms" 就飘到 905ms、暖机代价从 +13% 飘到 +42%，报了两个假红。
   带时间阈值的门（`warmboot` / `fixed-timestep` / `lampvol` / `festival`…）都怕这个。
   ⇒ **同一台机器只跑一条验证链**，其余等它跑完。
2. **端口只有一个**。`npm run serve` 固定 8935。两个工作区同时起服务，第二个会失败
   （探针用的是随机端口，不受影响，只有手动看页面时要注意）。
3. **共享产物必须串行**。`src/16-actors.js` 的行为一改，`probe/_actor-sim/baseline/*.json.gz`
   四份基线就得重录；两个任务同时重录 = 必冲突。这类任务不要拆开并行。

## 三、怎么开一个任务

### 方式 A：在这个 Claude 应用里直接说（日常首选）

```
给这个任务单开一个会话去做：<一句话描述>，改完跑 npm run check 和 npm test
```

我会用独立 worktree 起一个新会话（它有自己的目录和分支），跑完给你一个分支和结论。
**你只需要看结论 + diff**，不用记命令。

### 方式 B：自己用脚本开（给 Trae / Cursor / Codex 用）

```bash
tools/task-worktree.sh new fix-lint
```

它会做三件事：建目录 `../suzhou-garden-wt/fix-lint`、建分支 `task/fix-lint`、
把主仓库的 `node_modules` 联接过来（省 83MB 与一次 `npm ci`）。然后：

```bash
cd ../suzhou-garden-wt/fix-lint
```

在这个目录里开你的 AI 工具，贴下面的任务卡。

### 方式 C：看有哪些在跑

```bash
tools/task-worktree.sh list      # 列出全部工作区
tools/task-worktree.sh done fix-lint   # 收工：删目录，分支保留
```

## 四、任务卡模板（复制后填空）

> 一张卡 = 一个任务 = 一次可验收的改动。**不要写"优化一下整个项目"**。

```
任务：<一句话，动词开头：修/加/换/删>
背景：<为什么做，哪个现象或哪条门在报>
允许改动：<把文件列出来，越窄越好，例如 src/06k-willow.js、probe/willow-audit.mjs>
不要动：src/16-actors.js、probe/_actor-sim/baseline/（这两个是本项目最容易冲突的）
验收：
  1) npm run check
  2) npm test
  3) npm run verify -- --changed
完成标准：三条命令全绿 + 一个 git commit + 一段"改了哪些文件、为什么、还有什么风险"
```

### 拆卡的三条规矩

- 每张卡改 **1~3 个文件**；超过 5 个就再拆。
- 两张卡不能出现在同一份"允许改动"里。
- 有先后依赖的（比如先改数据源再改门禁），写成串行，不要硬并行。

## 五、收工：三条命令，按顺序

```bash
npm run check                    # 1 秒：语法/编码/未定义标识符
npm test                         # 约 2 分钟：冒烟 56 项
npm run verify -- --changed      # 按改动面挑门（本项目自己的映射，见 verify-all.mjs）
```

⚠️ `--changed` 只适合日常；**发版前仍须全量 `npm run verify`**。
⚠️ 全量跑的时候别开别的浏览器任务，也不要同时开第二个工作区跑门。

合并顺序：先合"基础设施/门禁"，再合"产品代码"，最后合"文档"。冲突了就是卡没拆好，
回去把重叠的部分再拆开，别硬解。

## 六、不要做的事

- ❌ 不要为了并行去装向量库 / AST 索引。这个仓库用 `rg` 就够：58 个模块、单文件
  最大 4500 行，检索成本远低于索引的维护成本。
- ❌ 不要一次开 5 条以上改码任务。先跑 2 条两周，看"返工率"再决定加不加。
- ❌ 不要让两个任务同时动 `src/16-actors.js`（人物、马车、马厩），它牵着四份回放基线。
- ❌ 不要把"整个项目"当成一次任务。那正是把 token 烧在重复理解上的写法。
