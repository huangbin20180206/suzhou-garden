# 客人到访 · 动线与动作编排（需求 + 技术规划）

> 2026-10-23 记录。需求由老黄口述；技术限制与分期由实施侧整理。
> 状态：**只记录与规划，尚未实现**（除"客人站在门口"这一静态落位已上线，提交 80be5f3）。

## 1. 需求（老黄原话整理）

主序列（**先做这一段**）：

1. 客人从**马厩**出发，沿**石板路**走到**院子门口**（月洞门）。
2. **主人出门相迎**。
3. 两人**相互作揖**。
4. 两人**并排**从入口 → **小桥** → **主堂**。
5. 在**主堂的椅子上坐下喝茶**。

后续（有时间精力再补，动线本身还没定）：

- 客人**坐马车**到马厩、**下马/下车**的接续段；
- 喝完茶之后的其它动作（送客 / 游园 / 回马厩等）。

## 3. 技术限制（会直接决定动作怎么编排）

1. **动作全是程序化骨骼驱动，没有动画剪辑**。每个动作 = 一组骨骼角度曲线 + 权重过渡；
   新增"作揖"就是给脊柱/大臂写一段 2~3s 的曲线，成本不高，但**必须逐帧可中断**。
2. **走路只有两点往复**。要走"马厩→门→桥→堂"必须先把 `tickRoute` 升级成
   **多航点 + once/pingpong 两种收尾**，否则第二个点之后就掉头。
3. **长袍角色坐椅子是风险点**：客人只有 6 根**单段**裙骨（`Skirt0..5`，髋→下摆）。
   跪坐（文士抚琴）已验证；**坐椅子**髋关节折 90° 时，单段裙骨的下摆会插进椅子/地面，
   需要实测（必要时改成两段裙骨 `seg=2` 重新导出）。
4. **两人对位不是"各走各的"**：作揖要求两人在固定点、面对面、时间对齐；
   并排走要求横向偏移固定 + 同速 + 同一条航点线（否则会错身/穿模）。
   ⇒ 需要一个极小的"导演层"：一段状态机，按"某演员到位 / 某动作播完"推进。
5. **桥面/台阶的 y 必须逐点取踏面**。桥是拱起的、堂前有月台；用地形高度会陷进桥面。
6. **主人（文士）身上有互斥动作状态机**（捧卷读 ↔ 端茶）。编舞开始前要先让他退出这套
   日常循环，否则会出现"边走边端着茶盏"。
7. **客人现在站在门口**（`route: null`）。一旦加动线，他的初始位置要改成"马厩起点"，
   否则每次进园他都凭空出现在门口。

## 4. 分期实施方案

### S1 · 多航点寻路（基础，必须先做）
- `tickRoute` 支持 `pts.length > 2` 与 `mode: 'once' | 'pingpong'`；
- 新增 `actorGoTo(id, pts, speed)`：把一条航点线交给某个演员，走到终点后停在待机；
- 新增 `actorArrived(id)` 之类的查询，给导演层用。
- 验收：客人从马厩 (40,4.2) 沿石板路 9 个控制点走到 (0,24.55)，全程脚底贴踏面、
  不穿栅栏/不踩进草地，走完停在门口。

### S2 · 迎客 + 作揖 —— **已实现**（2026-10-23）
- 主人从堂前 (1.2,−5.7) 出发，沿 `HOST_GREET_PTS`（16-actors 顶部常量）走到门内
  (0.15,19.75)，站在客人 (0.15,20.9) 对面；
- 导演层 `VISIT` 四相：`idle`（等 `guest.arrived`）→ `stow`（0.55s 把卷轴放下，
  不能"粘在手上飘着走"）→ `walk`（主人走一趟）→ `face`（站住互指，≥1.2s）→
  `bow`（同时起落）→ `done`；全程不用墙钟，推进只读演员自己的状态；
- 作揖幅度：躯干前俯 0.62rad、头低 0.12rad、两手在胸前合拢，起 0.70s / 停 1.00s / 落 0.70s；
- 到访期间文士的"捧卷 ↔ 端茶"状态机**退出**（`visiting`），卷轴用 0.55s 收回而不是瞬灭；
- 验收脚本 `outputs/_diag/guest-visit-check.mjs`（17 项：到站先后、脚底贴踏面、
  间距、朝向、手位高度/间距/高差/横偏、前俯可读、无捧卷端茶、礼毕、零 pageerror）+ 三张图。

### S3 · 并排同行（门 → 桥 → 堂）
- 航点 = **S2 路线的反向**（已实测可走，见 §6）：
  门口 (0.15,20.9) → (9,19.6) → (12.5,18.8) → (13.5,17) → (13.3,15) → (12.5,13.8) →
  (11,13.5) → (9.5,13.4) → (8.7,13.2) → (8.3,12.8) → (8.3,11.2) → (8.3,9.6) →
  (8.3,4.6 桥心) → (8.3,−2) → (7.6,−3.2) → (3.5,−5.4) → (1.2,−5.7)；
- 并排 = 同一条航点线 + **横向 ±0.45m** 的固定偏移（主人靠内侧），同速 0.62 m/s；
  ⚠️ 桥面只有 2.9m 宽、两侧有栏杆，并排时横向偏移要按"桥面中心线 ±0.45"算，不能按世界 x 加；
- 验收：两人间距在整段里保持 0.85~1.05m、不重叠、上桥时脚不穿桥面。

#### S3 · **已实现**（2026-10-23）

- 相位在 S2 的 `bow` 之后接两段：`line`（各自走到并排线的起点，谁先到谁站着等）
  → `pair`（并肩走完整段）→ `hall`（到堂前站定，S4 从这里接）；
- **两个人由同一条弧长 s 驱动**（`pathTable/pathAt`，tickVisit 的 `pair` 相）：
  位置 = 中心线点 + 法线 ×(∓gap)，s 相同 ⇒ 间距恒为 0.90m；
  转角处两人**一起站住转**（s 不推进），转完继续；
- 两人各自的踏面独立采样（`sampleFloorNear`），floorMax 抬到 2.45（桥面最高 2.10）；
- 验收脚本 `outputs/_diag/guest-pair-check.mjs`（10 项）：八个相位都走到、间距
  0.90~0.90m、并排全程脚底−踏面 ≤0.06m（实测 0.043）、过桥 floorY ≥1.10（实测 1.55）、
  过桥两人 x ∈[7.85,8.75] 在桥面内、终态到堂前 ±1.6m（实测各 0.45）、零 pageerror。

## 6. 实测几何（2026-10-23，S2 期间量出来的，S3/S4 直接用）

用 `outputs/_diag/host-layers.mjs`（逐点列出**所有**命中面）和
`host-route-verify.mjs`（沿线 0.25m 一档量踏面 + 胸口净距）量得：

| 位置 | 实测 |
|---|---|
| 堂前地坪 | −0.20m；月台台基 1.24m，前沿两道台阶 0.72 / 0.31 |
| 拱桥 | x 6.95~9.85、z −0.1~9.1；桥面 **1.30(北) → 2.10(桥心) → 1.30(南)**；桥心 x≈8.3 |
| 桥北踏步 | (7.6,−3.2) 一带 0.69m 一级；直接从地面切到桥面是 1.3m 的坎 |
| 桥南廊道 | z 9.6~11.2 仍是**架高廊道**（面 1.30m、下面还有地面 −0.1）；z 12~13.4 逐级降到 0.38 |
| 南园假山 | z 13.5~19.3 / x 0~4.5 是**一整块**（胸口净距 0），只能绕东侧空地 x 12~16 |
| 门内地坪 | −0.42m；月洞门洞宽约 2m |

⚠️ **踩过的坑**（下一段别重复）：
1. **"第一个命中面"会被树冠骗、"最低面"会被桥下地面骗、"最近面"会被池底骗**——
   这段路同时有"架高廊道 + 下面地面 + 水面 + 树冠"四层，单一口径必错一次。
   最终做法：只认不透明面，在 `[当前 −0.60, 当前 +0.42]` 这个"一步之内"的窗口里
   取**最高**面（没有才回落成最近），见 `sampleFloorNear`。
   ⚠️ **方向不同，口径不同**：S2 是往**下**走，"离当前最近"就够；
   S3 反向往**上**走时"最近"必然选到脚下的草地 ⇒ 整段从廊道底下、桥底下穿过
   （实测 floorY 读到 −0.99 = 桥下地面）。所以别把这条规则"简化"回最近。
2. **门内地坪比堂前低 0.22m**：判据里凡是用世界 y 比"手在胸前"，换个位置就假红/假绿，
   一律改成**相对脚底**。
3. **作揖的手位必须在"前俯摆上"之后再解**：只按站姿解出来的手会掉到胯部（差 0.4m）。
4. **两个人"各追各的航点"走不出并排**：转角处的站住转 + 外线更长会累积成纵向错位
   （实测间距从 0.90 漂到 2.83m，读作"主人在前面领路"）。正解＝同一条弧长驱动两人。
5. **垂直跟随的速度**：跟随型原来 18/s，在 0.2m 的台阶上留 8.6cm 瞬时悬空；
   改 34/s 后 0.043m（时间常数 29ms）。
