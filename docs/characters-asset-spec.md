## 0. 这条线与现有 `08b-figures.js` 的关系

| | 现有（剪影路线，已上线） | 本规格（GLB 半写实路线，待生成） |

## 1. 通用约定（四件模型全部适用）

| 项 | 约定 | 为什么 |
|---|---|---|
| 单位 | **1 单位 = 1 米**（three.js 场景单位） | 全项目约定 |
| 朝向 | **正面 = +Z**（glTF 坐标） | 与 `08b` 的"模型正面 = +z"一致；`loadAssetOnce` 归一化后不再转 |
| 原点 | **脚底中心**：`x/z` 居中、`y = 0` 在脚掌最低点 | `loadAssetOnce` 会把底部对齐到 0，原点在腰上会二次偏移 |
| 姿势 | **A 姿势**（双臂离身体约 45°，掌心朝内/朝下，双腿微开 ~10°，脚掌贴地） | UniRig 保留此姿势；T 姿势会让腋下权重与肩形走样 |
| 面数 | **8k~15k 三角面**（见各模型预算） | 项目现有全场景 ~180 万三角，单件上限见 §5 |
| 贴图 | **1 张 1K（1024²）图集** + **可选 1 张 1K 法线** | 一张图集 = 一次 draw call 的贴图绑定；多张会拆材质 |
| 材质 | `metallic = 0`、`roughness 0.80~0.95`、无 emissive、无透明（披帛除外） | AI 生成件常带 `metallicFactor = 1`，低画质档无强环境反射时**渲染成黑块**（2026-10-03 鹦鹉踩过） |
| 骨骼 | **30~45 骨**，手指可省略 | 见 §4 |
| 文件 | `assets/fig-scholar.glb` / `fig-lady.glb` / `fig-laborer.glb` / `fig-child.glb` | `fig-` 前缀与 `figures` 模块对齐；**单件 ≤ 1.5MB** |
| 压缩 | **不用 Draco / 不用 KTX2** | 项目离线环境里 Draco 解码器要拉 wasm，`probe` 会报 4 条 pageerror；现有资产全部无压缩 |

## 2. 四个模型

### 2.1 文士（Scholar）· `fig-scholar.glb`

| 项 | 值 |
|---|---|
| 用途 | 先生晨课、负手观荷、对弈、抚琴；**P1 第一个接入的角色**（站姿+走路即可验证管线） |
| 身高 | **1.72 m** |
| 三角面 | **10k~13k**（目标 12k） |
| 贴图 | 1K 图集（袍/缘/腰/鞋/脸/发）+ 1K 法线（可选，布料织纹） |
| 骨骼 | **32~40**（含 5 根裙骨、2 根发带骨） |
| 朝向 | 正面 +Z；Blender 里检查时应为**朝 −Y**（导出 `export_yup=True` 后 → +Z） |
| A 姿势 | 双臂 45°、掌心朝内；**不要**负手、不要交叠、不要袖手 |
| 禁带道具 | 折扇、书卷、毛笔、茶盏、棋盘棋子、玉佩、剑、伞、包袱、**底座/地台/影子面片** |
| 服装要点 | 直裰/长衫（交领右衽）、宽袖收至腕、深色腰带、米白衣缘、下摆离地 2~4cm |
| 风格关键词 | 半写实、低模、工笔淡彩、哑光布料、**不要照片级皮肤**、不要次表面散射、不要高光漆面 |

**识别特征**（低模下认人靠这三条）：A 形长袍轮廓 + 束发（小黑冠/网巾）+ 冷蓝配米白衣缘。
袍色建议落在 `FIG_PALETTE.indigo` 一族（0x4A6C9B 附近）——与草坪绿 #457441 的 RGB 距离够大。

### 2.2 仕女（Lady）· `fig-lady.glb`

| 项 | 值 |
|---|---|
| 用途 | 井边汲水、游廊夜步、水榭品茗、赏荷 |
| 身高 | **1.63 m** |
| 三角面 | **12k~15k**（裙摆是面积大户，目标 14k） |
| 贴图 | 1K 图集 + 1K 法线（可选） |
| 骨骼 | **38~45**（**裙骨 6 根** + 披帛骨 2~4 根） |
| 朝向 / A 姿势 | 同 §1 |
| 禁带道具 | 团扇、花篮、水桶、伞、首饰链（悬空细件）、底座 |
| 服装要点 | 短襦 + 高腰长裙（襦裙）、**披帛搭在两臂上（贴身，不悬空）**、发髻（高髻 + 少量发饰几何） |
| 风格关键词 | 同上，另加"裙褶用低频手绘褶皱，不要高频布料噪声" |

**披帛的处理（重要）**：披帛是**悬空薄片**，UniRig 几乎必然绑错（一半绑 chest、一半绑小臂，
摆动时被撕开）。两条都是可接受的：
- **推荐**：生成时让披帛**两端搭在小臂上、中段贴背**（几何连续、不飘在空中），为它预留 2~4 根骨；
- **兜底**：若绑骨后披帛顶点的主骨 >60% 落在 thigh/shin（裙骨）上，就**不导出披帛**（局部删几何），
  接入后由道具层用两根 tube 另做（14-props 已有类似做法）。

裙摆同理：**裙骨 ≥6 根**（前/后/左/右各 1~2），否则走路时裙子会整片跟着大腿左右翻。

## 3. 贴图与材质细则

### 3.1 1K 图集的 UV 分区（建议）

| 区 | 占比 | 内容 | 硬要求 |
|---|---|---|---|
| 脸/头 | ≈ 22% | 肤色、五官、发际线 | **脸区 ≥ 200×200px**；**睁眼**：眼白杏仁 + 虹膜 + 瞳 + 一点高光；有颧宽、有下颌、发际线落在额头上 |
| 头发/发髻 | ≈ 8% | 近黑 #1C2029 一族的发色 | 与袍色明度差 ≥ 25 |
| 袍身 | ≈ 38% | 主色 + 低频褶皱 | 褶皱是**手绘明暗**，不是法线细节堆出来的 |
| 衣缘/腰带 | ≈ 12% | 米白 / 深色 | 与袍身 ΔRGB ≥ 60（同框可区分判据的阈值） |
| 手/脚/鞋 | ≈ 12% | 肤色 + 布鞋 | 手部给指缝暗线即可 |
| 杂项 | ≈ 8% | 披帛/布巾/腰带结 | — |

> **为什么脸区要 ≥200px**：2026-10-20 的教训 —— 现有剪影的脸贴图按"3m 外可读"画，五官只有
> 2~3px 线，0.5m 近看读成"一条裂缝 + 长蛋脸"，老黄的原话是"近看跟外星人一样"。新模型默认会被
> 拉到近景（P1 验收要出近景图），脸区不够大就是同一类返工。

### 3.2 材质

- `metallic = 0`（**硬性**）；`roughness` 0.80~0.95（布料）、0.68~0.75（皮肤）。
- 不要 `clearcoat` / `sheen` / `transmission` / `emissive`（灯笼/灯会另有自发光层）。
- 披帛若必须半透：`alpha` 通道 + `alphaTest ≥ 0.5`（不要 `transparent + depthWrite:false`，
  会被 GTAO 的 pre-pass 与折射层各自处理错）。
- **不要**烘焙环境光/阴影进 albedo（会有"自带脏影"）。

### 3.3 法线（可选）

1K 法线只做**布料织纹/褶皱走向**，`normalScale` 建议 0.25~0.4。不要皮革/金属细节。
若生成阶段拿不到法线，宁可不带 —— 一张错的法线（如把 AO 烘进法线）比没有更糟。

## 4. 骨骼规范（30~45 骨）

推荐骨架（括号内为骨数）：

```
root(1) → hips(1) → spine01(1) → spine02(1) → chest(1) → neck(1) → head(1)      = 7
clavicle.L/R(2) → upperarm.L/R(2) → lowerarm.L/R(2) → hand.L/R(2)               = 8   → 15
thigh.L/R(2) → shin.L/R(2) → foot.L/R(2) → toe.L/R(2)                            = 8   → 23
skirt.F/B/L/R(4~6)  · 披帛.L/R(2~4)  · 发带/发髻(2)                              = 8~12 → 31~35
手指：每手 5 根（可选，+10）                                                      = 41~45
```

- **必须**有 `root`（脚底原点、世界朝向），否则接入时无法统一位移/朝向。
- 骨名不要用中文/空格；`DEF-`/`ORG-` 双链**不要**出现在人物上（那是 Rigify 导出的马带来的，
  项目里为它写过专门的"别猜骨名"教训）。
- **权重**：不允许有"零权重顶点"（会留在原位，人一动就有一块肉粘在空中）。Blender 里
  `Weight Paint → Weights → Clean` 后检查每个顶点的权重和 ≥ 0.999。
- 不要 IK / 约束 / 驱动（glTF 不导出，接入后会变成静止或乱转的骨）。

## 5. 硬性预算与项目现存约束

| 约束 | 值 / 做法 | 出处 |
|---|---|---|
| 单件体积 | **≤ 1.5MB**（1K 图集 + 12k 面 ≈ 0.6~1.1MB，余量够） | 项目既有预载预算 |
| 单件三角面 | 8k~15k | 本规格 |
| 静态阴影 | `renderer.shadowMap.autoUpdate = false` ⇒ **异步到场/换装后必须** `markCasterBoxDirty()` + `renderer.shadowMap.needsUpdate = true`，否则地板上有旧阴影、新人不投影 | 2026-10-10 马厩 |
| 移动角色 | **不进静态阴影图**：`castShadow = false` + 贴地软阴影片（`makeSoftAlphaTex`，用 `map` **不是** `alphaMap`） | 马步态同款 |
| 私有随机流 | 新增落点/动作相位/抖动一律 `mulberry32(<固定种子>)`；**不许** `Math.random()`（装配期），也不许多抽一次全局 `rr()/rnd()` | 铁律 1 + layout-fingerprint |
| 合并 | 会动的角色网格打 `userData.noMerge = true`（`mergeStatics` 只认这个标记、逐网格判定、不继承父级） | 2026-10-10 |
| 预载 | 新 GLB 必须同时进 `src/13-preload.js` 的 `PRELOAD_MANIFEST` 与 `sw.js` 的 `GLBS`（`preload-manifest-sync.mjs` 会逐项比对集合 + bytes） | 2026-09-27 双清单 |
| SW 版本 | 新增 `assets/*.glb`（cache-first 资产）⇒ **`ASSET_CACHE` 后缀 +1**（当前 `suzhou-garden-assets-v13` → v14）。`CACHE` 应用版本只在 cache-first 的 SHELL 成员（`docs/cover.jpg` / `icons/garden.svg`）变化时才 bump；`index.html` / `src/*.js` / `vendor.js` / `manifest.webmanifest` 是 network-first，**不 bump** | `sw.js` 头部 2026-10-12 收窄后的规矩 |
| 相机 | 动作/机位若超出 `controls.target` 钳制范围，先扩钳制（`maxPolarAngle = 88.6°` 意味着**镜头永远抬不起来**） | 2026-10-05 |

## 6. UniRig 绑骨约束（不是 MIA）

| 项 | 要求 |
|---|---|
| 引擎 | **`unirig`**（`unirig_rig(engine='unirig')`）。**不要 MIA** —— MIA 输出 Mixamo 22 骨 + 强制 T 姿势，与本规格的 30~45 骨 / A 姿势直接冲突 |
| 输入姿势 | **保留 A 姿势**。若生成件是 T 姿势，先在 Blender 里把手臂放下来（`prep_character.py` 只做缩放/居中/偏航，**不改姿势**） |
| 裙骨 | 长袍/裙摆**必须**有独立裙骨（≥4，仕女 ≥6）。绑完后逐顶点检查：裙摆顶点主骨落在 `thigh/shin` 上 ⇒ 走路时裙子会跟着大腿翻，需手工补裙骨并重分配权重 |
| 手指 | **可省略**。省 10 根骨，权重更好分，低模下手指本来只有几十像素 |
| 骨名 | UniRig 输出的骨名不可依赖（可能是 `Bone_001` 之类）。接入时**先读 skinIndex/skinWeight 的主骨名**再写驱动 —— "猜骨名"是项目里最容易整轮空转的写法（马的双链事故） |
| 输出检查 | `node research/characters/validate_glb.mjs <out.glb> --require-skin`：`skins=1`、`joints 30~45`、`animations` 应为 0（动作由 JS 程序化驱动，不烘焙 clip） |
| 顶点数上限 | UniRig 对超密网格会降级；8k~15k 三角面在它的舒适区 |

**绑骨后立刻做的一件事**：在 Blender 里把 `hips` 抬高 0.10m、`thigh` 各转 20°，
看裙摆/披帛有没有被撕开。撕开就说明权重没分对，别等到接入 JS 才发现。

## 7. 验收判据（每个模型都要过）

1. `node research/characters/validate_glb.mjs assets/fig-xxx.glb --require-skin`
   —— `meshes ≥ 1`、`POSITION/NORMAL/TEXCOORD_0` 全有、`skins = 1`、`joints 30~45`、
   三角面落在预算内、退出码 0。
2. `prep_character.py` 的打印：`高度 = 1.72±0.005`、`脚底 z ≈ 0`、`x/y 居中的残差 < 1mm`。
3. Blender 四视图截图（front / left / back / right）：**正面必须是 +Z 那张**（导出后用 three 再看一次）。
4. 近景截图：脸区在 0.5~1.0m 距离下**读得出眼白、虹膜、唇**（对照 §3.1 的教训）。
5. 与草坪同框：袍色对 #457441 的 RGB 距离 ≥ 60（`probe/figure-palette.mjs` 同一把尺子）。
6. 站姿 + 走路各 10 秒：脚不穿地、裙摆不穿过腿、头不抖（角速度判据，见 `macaw-guard` 的做法）。

## 8. 接入前要先处理的三个已知接口问题

1. **`loadAssetOnce` 的 `src.clone(true)` 不适合骨骼人物**。three 的 `SkinnedMesh.clone()` 会
   **共享同一个 `Skeleton`** ⇒ 四个角色会共用一套骨、动作完全同步。正确做法是
   `SkeletonUtils.clone()`；但 `vendor.js` **目前没有导出它**（`build-entry.js` 只导出了
   `mergeGeometries`，实测 `vendor.js` 里 `SkeletonUtils`/`cloneSkeleton` 命中 0 次）。
   ⇒ 接 P1 时要先给 `build-entry.js` 加一行 `export { clone as cloneSkeleton } from
   'three/examples/jsm/utils/SkeletonUtils.js'` 并 `npm run build:vendor`（改的是构建入口与
   产物，不是本轮允许新增的文件，故留到 P1 做）。
2. **`probe/figure-audit.mjs` 的配色判据读的是 `material.color`**（`FIG_PALETTE` 的色值）。
   GLB 人物的 `material.color` 是白色、真色在 1K 图集里 ⇒ 新角色接进去会直接红。
   两条路（选一条并注释写明理由）：给新角色暴露等价的 `userData.palette = {robe, trim, sash}`
   供判据读取；或把"GLB 人物"从该判据的取样集里排除，另建一条"贴图主色采样"判据。
3. **`figure-audit` 的脚底/朝向判据依赖** `userData.baseY` / `rotation.order='YXZ'` /
   `rotation.y = atan2(dx,dz)`。GLB 角色接进去时要沿用这套口径（`baseY` 每帧被 11-loop 写回），
   否则"脚陷进台基 / 侧身滑行"那两条老缺陷会原样复发。
