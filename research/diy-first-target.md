## 2. 首制目标：**石灯笼**（湖心小亭/望柱为什么不当第一个）

| 候选 | 判定 | 证据 |
|---|---|---|
| **望柱** | ❌ **已有，不再造** | `05-water.js:508-520` 桥上 4 根望柱 + 栏板；`03-factory.js:545` 另有整套栏杆/美人靠 |
| **湖心小亭** | ❌ 不当**第一个**（不是否掉） | ① 池是**单块葫芦形、无岛**（`05-water.js:12-24`）⇒ 湖心亭要先动地形/造岛，属"大工程垫底"；② 园内已有临水亭 `makeWaterPavilion`（W8×D7），第二个亭属**同类重复**；③ 攒尖翘檐是本类里最难的顶型，首件就啃它风险高 |
| **树** | ❌ 不当第一个 | 树已程序化成片（§1.2），属"换更好的"而非"缺"，且树的面数/风动/LOD 影响面最大 |
| **石灯笼** | ✅ **首制** | 0 命中（§1.3）=真缺口；体量最小、部件天然可拆、白天当小品夜里当亮点（项目已有 灯会/夜 状态）、不改地形、不与既有同类重复 |

**一句话**：选"真缺 + 最小 + 立刻出效果"的那件，把 Blender 流程先跑通一遍；亭廊树留给第二批。

## 3. 规格（可直接照做）

### 3.1 最大外包尺寸

以场景真人尺度为尺（人头高 y=1.445 ⇒ 身高 ≈1.6m，`08-assemble:904`；桥望柱 0.82+球头 ≈1.0m，`05-water:513-517`；栏杆 h=1.05，`03-factory:545`）：

| 项 | 值 |
|---|---|
| **总高（含宝珠）** | **1.05 m** —— 与栏杆齐、略高于望柱 |
| **笠最大外径** | **0.55 m** |
| **基座外径** | **0.45 m**（含埋地缘 0.03 m） |
| **外包盒** | **0.55 × 0.55 × 1.05 m**（L×W×H） |
| 部件高度配比 | 基座 0.16 / 柱身 0.34 / 中台 0.10 / 火袋 0.24 / 笠 0.16 / 宝珠 0.05 |

### 3.2 面数预算（**代价数字，不是门**）

| 参照物 | 实测 | 出处 |
|---|---|---|
| 主峰 `assets/boulder-hero.glb` | **66,122 tris / 5.94 MB**（1 mesh、1 材质、1 buffer、3 张 JPEG、`extensionsUsed=[]`） | 本轮解析该 GLB 得出（与派单里"6.6 万面 5.94MB"一致） |
| 现有 props | koi 203 KB、Turtle 398 KB、BananaPlant 261 KB | assets/ 实测 |
| 当前 assets 总量 | 7 文件 **3.68 MB** | 本轮累加 |

**建议目标：≤ 8,000 tris、GLB ≤ 400 KB**（= 主峰的 1/8 面、1/15 体积；理由：它在最近机位上也只占画幅高约 3.9°/46° = **8.5%**，15m 距离用不到主峰级密度）。

代价换算：+400 KB ⇒ assets **3.68 → 4.08 MB（+10.9%）**；若按主峰级做 ⇒ **+163%**。只报数字，做多做少由效果定。

### 3.3 部件拆分（便于 LOD）

| # | 部件（导出节点名） | 形态要点 |
|---|---|---|
| 1 | `base` 基座 | 八角须弥座，埋地 0.03，四边做 2mm 磨损倒角 |
| 2 | `shaft` 柱身 | 八角直柱 + 束腰，不做贴花 |
| 3 | `platform` 中台 | 八角承台，下沿出挑 0.04 |
| 4 | `lamp` 火袋 | **四面开窗**（窗 0.13×0.15、四角圆角 R0.02，窗内壁留 0.02 厚） |
| 5 | `roof` 笠 | 四角翘檐，檐口出挑 0.10，底下做 4 条肋 |
| 6 | `finial` 宝珠 | 球 + 宝珠座 |

**LOD 分档**：
- **L0**（近景/≤8m）：6 件全在，窗内壁可见
- **L1**（中景 8–30m）：`base+shaft+platform` 合并、`lamp+roof+finial` 合并 ⇒ **2 个网格**，删窗内壁
- **L2**（远景 >30m）：单网格代理（盒 0.5×0.5×1.05，**≤40 tris**）

> 首件只做 L0；L1/L2 留到接线时按 perf 再拆（本单不编码）。

### 3.4 Blender 导出设置（**逐条对齐 boulder-hero 的干净结构**）

| 设置 | 取值 | 依据 |
|---|---|---|
| 格式 | **glTF 2.0 · Binary (.glb)** | boulder-hero 为单 .glb |
| 压缩扩展 | **不启用** Draco / KTX2 / meshopt | boulder-hero `extensionsUsed = []`（实测） |
| buffer | **1 个内嵌 buffer** | boulder-hero `buffers=1`（实测） |
| 贴图格式 | **JPEG**（质量 ~90）；**优先不带 alpha**（开窗用几何挖穿，不用透明贴） | boulder-hero `images = 3 × image/jpeg`（实测） |
| 材质 | **单一** `stone_lantern`（Metallic-Roughness） | boulder-hero `materials=1`（实测） |
| Apply Modifiers | ✔ | 避免节点里带缩放 |
| Apply Transforms | ✔（`Ctrl+A` 全清） | 让 node 平移/缩放归零，接入时 `position.set` 才是真值 |
| 导出相机/灯光 | ✘ 不导 | 场景光照归项目 |
| 缩放 | **1 Blender 单位 = 1 m**，按 §3.1 真实尺寸建 | 不靠 scale 变换凑尺寸 |
| 三角化 | 导出时 triangulate，**不提前手动三角化**（留 N-gon 给倒角/布尔） | — |
| 节点/网格命名 | 就用 §3.3 那 6 个英文名 | 接线与 LOD 都按名取件 |

**自检（导出后 30 秒可查）**：`meshes=1（或 6，取决于是否分对象导出）· materials=1 · buffers=1 · extensionsUsed=[] · images ≤2` —— 与 boulder-hero 同构即通过。

### 3.5 摆位（**本轮实测算出，非拍脑袋**）

落位一律走既有助手 `08-assemble.js:700` 的 `root.position.set(x, groundHeight(x,z), z)`，**不要手写 y**（全园地形不是 0，草地 −0.14~−0.21，见 `08-assemble:685`；水位 `CFG.water = 0`，`00-config.js:8`）。

| 位 | 坐标 (x, z) | 地面 y | 为什么选它（实测） |
|---|---|---|---|
| **主位** | **(4.0, −3.8)** 北岸 | **0.053** | 距岸线 **1.62 m**（岸石带半径 ≤0.75 m ⇒ 净隙 **0.65 m**，不相撞）· 最近既有物 **corridor 8.8 m** · 离两个南岸导览机位均 ≥4.5 m · **入画 2/3 机位**：桥机位水平偏轴 **31.7° @16.2 m** ✓、koi 机位 **14.7° @15.3 m** ✓（半水平 FOV **37.0°**、半垂直 **23°**，`02-scene:104` vfov=46 / 16:9） |
| **备位** | **(18.1, 5.2)** 亭东 | **−0.197** | 距亭台基 **2.98 m** 净空（台基 AABB 半宽 5.3/5.8，`04:398`）· 最近物 orchidS **3.92 m** · **亭机位 14.9° @14.1 m** ✓ 正入画、桥机位 26.2° @17.9 m ✓ |

**朝向**：火袋**四面开窗** ⇒ 朝向无所谓（夜景也四面透光）。若坚持单面开口：主位开口朝 **+x（东，正对桥北落点）**，备位开口朝 **−x（西，正对荷风四面）**。

**同一件摆两处**：一个 GLB 两处实例，增量≈0；先做主位，备位等效果确认再摆。

**明确否掉的落点（本轮算出，别再踩）**：
- **(7.94,10.22) / (8.4,10.4)** —— 压在拱桥南台与台阶上（桥 AABB 世界 **x 6.85–9.95、z −3.5–12.7**，由 `span=9.4` + landing ±5.7 + 台阶 ±7.92 经 rot.y=π/2 换算）⇒ 相撞。
- **(6.65,9.99)** —— 离桥仅 **0.20 m**，擦边。
- **(2~3.5, 10.8~12.0)** 一片 —— 正好是 `koi` 机位 `(0,1.55,11.4)` 与 `bridge` 机位 `(1.8,1.35,12.6)` 的**站位脚下**，相机飞过去就贴脸。

## 4. 接线代价与验收（**说明，本单不编码**）

| 事项 | 内容 |
|---|---|
| 需要动的文件 | `assets/stone-lantern.glb` · `src/13-preload.js` 的 `PRELOAD_MANIFEST` · `sw.js` 的 `GLBS` · `src/08-assemble.js` 摆位 |
| ⚠️ 两份投影必须同步 | `GLBS` 与 `PRELOAD_MANIFEST` 是同一批资产的两个投影，只改一处会"在线重复下载"或"PWA 断网拿不到"（`sw.js:128` 段注）；有门 `probe/preload-manifest-sync.mjs` 钉着 |
| 布局指纹 | 加资产 **必然改布局指纹**（现基线 1022579009）；白板已记：**指纹重拍 + 局部门禁可接受**（用户 2026-10-14 口径） |
| 光照 | **建议 emissive-only、不加动态光源** —— 项目既有口径就是"不新增真光源"（`06c-organs.js:451`：全场真光源仍只有灯笼那 5 盏）；真加一盏灯会动渲染成本，而灯会态最坏帧已 **1288/1600（余量 312）** |
| 完成判据 | ① `npm run check` PASS ② GLB 结构计数对齐 §3.4 ③ 桥机位 + 亭机位各 1 张截图 ④ 接线后 layout-fingerprint 重拍 + 局部门禁跑绿 |
